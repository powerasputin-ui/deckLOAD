## 1. Задача

Пользователь попросил проверить логику остойчивости и убедиться, что в приложении есть все данные, которые нужны для расчёта. Разбор показал, что дело не только в недостающих полях. Вердикт стоит не на том основании.

Сейчас приложение ставит ✓ или ✕ по собственному расчёту:
- GM против одного числа `minGM` или общего ориентира 0,15 м;
- если введены кросс-кривые KN, ещё и по критериям IS Code, часть A, 2.2.

Одобренный формуляр судна даёт предел как кривую по осадке, а не одно число. В нём уже учтены все применимые критерии: общие, погоды или его замена, для судов снабжения. Приложение этого не знает. Поэтому зелёная галочка возможна там, где формуляр не выполнен.

### 1.1 Найдено в коде

Данные:

| Нужно для расчёта | Сейчас |
|---|---|
| Предел по формуляру | Одно число `minGM`, поля в интерфейсе нет. У «Кузнецова» 1,22 м — значение для одного случая загрузки (LC51) |
| Гидростатика по рабочему диапазону | Поле есть. У «Кузнецова» одна точка, поэтому любая другая загрузка — «оценка» |
| Предельная осадка по грузовой марке | Нет |
| Вода в трубах | Только необязательное ручное поле в конструкторе пакета труб. Вес прибавляется к весу груза и отдельно нигде не виден. У одиночных труб поля нет. В утверждённом расчёте «Кузнецова» воды 87 т на высоте 9,1 м |
| Обледенение | Нет |
| Отход и приход | Один набор танков на всё |
| Парусность, коэффициент полноты | Хранятся, но ни в одном расчёте не используются |
| Длина L по грузовой марке | Нет. Нужна для правила о воде в трубах |

Логика:

1. Кривая GZ не учитывает поперечное смещение центра тяжести. Поправка TCG·cos θ не вычитается, поэтому при крене плечи завышены.
2. «GZ ≥ 0,2 м при угле ≥ 30°» проверяется ровно при 30°. Кодекс требует 0,2 м на любом угле от 30° и выше, поэтому возможен ложный ✕.
3. Угол максимума GZ берётся по узлам таблицы, обычно через 10°. Критерий «≥ 25°» может ошибаться в обе стороны.
4. Угол заливания ограничивает и границу 30°, хотя по п. 2.2.1 он ограничивает только 40°.
5. Нет альтернативных критериев для судов снабжения (IS Code B 2.4.5). Широкому судну, которому кодекс разрешает этот набор, приложение показывает ✕ по части A.
6. Критерий погоды не считается. По изданию IS Code 2020 года судно снабжения от п. 2.3 освобождено, но взамен должно выполнять эквивалентные альтернативные критерии. Их приложение не знает.
7. Нет осадок носом и кормой и проверки по грузовой марке. LCF вводится, но не используется.

## 2. Решения пользователя

| Вопрос | Ответ |
|---|---|
| Что приложение говорит об остойчивости | Сверка с формуляром: GM не ниже предела из одобренного формуляра при текущей осадке. Кривая GZ и критерии — справка с пометкой «оценка» |
| В каком виде предел в формулярах | Неизвестно, формуляров на руках нет. Поэтому принимаются оба распространённых вида |
| Что показывать без предела | ✕, если GM ниже 0,15 м; иначе ⚠ «предел не задан». Ложной зелёной галочки нет |
| Вода в трубах | Считать автоматически по правилу IS Code, с ручной поправкой в тоннах |
| Состояния загрузки | Отход и приход, вердикт по худшему |
| Обледенение | Учитывать, включается переключателем |
| Когда делать | Перед этапом 3, отдельным этапом 2а. Итог — сразу и в PDF |

*Вывод, не факт:* формуляров у пользователей, судя по ответу, обычно нет. Тогда вердикт почти всегда будет ⚠. Польза сводится к трём вещам:
- поймать грубые ошибки: GM ниже 0,15 м и перегруз по марке;
- учесть воду в трубах и лёд;
- показать числа.

Это сознательный выбор: без формуляра приложение не может подтвердить остойчивость.

## 3. Данные

### 3.1 Судно (вводится один раз)

- **Предел по формуляру** `vessel.limit` — необязательный.
  - Вид: «мин. GM по осадке» или «макс. KG по водоизмещению».
  - Таблица из двух столбцов. Заполняется вставкой текста, как KN, или по ячейкам.
  - Строка «Источник», свободный текст: например, «Информация об остойчивости, табл. 5».
  - Значения между строками интерполируются линейно. За пределами таблицы предела нет — см. 5.
  - Заменяет `particulars.minGM`.
- **Предельная осадка по грузовой марке, м** `particulars.maxDraftM` — летняя, по свидетельству о грузовой марке.
- **Длина L по грузовой марке, м** `particulars.loadLineLengthM` — для правила о воде в трубах. Если не задана, берётся LBP, и проверка показывает ⚠: с LBP доля воды получается меньше, то есть не в запас.
- **Набор критериев для справки** `particulars.criteriaSet`: «IS Code, часть A 2.2» (по умолчанию) или «Судно снабжения, B 2.4.5».
- **Для льда:**
  - «Боковая площадь судна без груза, м²» и «Высота её центра над ватерлинией, м». Это нынешние `windageAreaM2` и `windageLeverM`: подпись меняется, данные остаются.
  - «Открытые палубы вне грузовой, м²» `particulars.otherExposedDeckAreaM2` и «их высота над килем, м» `particulars.otherExposedDeckVcgM`.
- Гидростатика и KN — как сейчас. Порожнее судно и система координат палубы не меняются.
- Высота палубы над килем (`shipFrame.heightAboveBaselineM`) служит и высотой борта для надводного борта. Для судна снабжения с гладкой главной палубой это одно и то же; оговорка в подсказке поля.

### 3.2 Состояния (вводятся один раз на расчёт)

- **Танки и запасы** `vessel.tanks`: два набора, «Отход» и «Приход», такие же строки, как нынешние «Переменные грузы». Кнопка «Скопировать из отхода».
- **Обледенение** `deck.icing`: переключатель. Лёд добавляется к приходу.
- Оба применяются ко всем рейсам расчёта. Рейсы в авто-режиме — повторы одного перехода. Они появляются и исчезают при правке груза, поэтому привязка к номеру рейса терялась бы.

### 3.3 Груз

- У труб новое поле **«Внутренний диаметр, мм»** `CargoItem.pipeInnerDiameterMm`. Трубой считается груз, для которого `isPipeShape` истинно, или пакет труб (`shape: 'pipe-nest'`). У трубы с покрытием наружный диаметр в приложении — с покрытием, поэтому внутренний задаётся отдельно, по стальной трубе.
- У пресетов труб внутренний диаметр заполняется сразу: их названия дают стальной диаметр и стенку. Например, «Ø813×30,2 НУБП-72» → 813 − 2 × 30,2 = 752,6 мм. У пресетов без стенки (гибкая труба и подобные) поле пустое.
- Необязательная поправка **«Вода в трубах, т»** `CargoItem.trappedWaterT` — на все трубы этого груза во всех рейсах, если цифра дана в проекте перевозки. Каждому штабелю достаётся доля по числу его труб. Поправка заменяет расчёт. Поле «Вода в трубах» конструктора пакета труб теперь пишет сюда, а не прибавляет воду к весу груза.
- До этапа 3 оба поля стоят в нынешней карточке груза у труб. На этапе 3 они переезжают в таблицу грузов.

### 3.4 Перенос сохранённых расчётов

- `minGM` превращается в таблицу «мин. GM по осадке» из одной строки — при осадке того случая загрузки, для которого это число дано. У «Кузнецова» это 1,22 м при 5,873 м (LC51). `minGM` приходит только из библиотеки, и у такого судна одна точка гидростатики — её осадка и берётся. При любой другой осадке предел оказывается «вне таблицы», и проверка показывает ⚠. Если точка гидростатики не одна, `minGM` не переносится, а остаётся подсказкой «было: мин. GM 1,22 м» в группе «Предел по формуляру».
- Старый набор `variableWeights` копируется в оба состояния. В панели видна пометка «Отход совпадает с приходом — проверьте». У «Кузнецова» эти танки из документа относятся к приходу (LC51 Arrival).
- Пакет труб, собранный с водой: его вес больше, чем число труб × вес трубы (`nest.pipeCount × nest.pipeWeightKg`). Разница переходит в `trappedWaterT`, а вес груза уменьшается до веса труб. Так вода не считается дважды.
- Грузам из пресетов труб, уже стоящим в расчётах, внутренний диаметр проставляется по названию пресета, если название совпадает.
- Остальные поля необязательные; у старых расчётов их просто нет.

## 4. Расчёт

Для каждого рейса считаются два состояния — отход и приход.

1. **Водоизмещение и центр тяжести** = порожнее судно + танки состояния + груз рейса + вода в трубах + лёд. Лёд входит только в приход и только при включённом обледенении.
2. **Вода в трубах** (IS Code B 2.4):
   - чистый объём = объём внутри труб + объём между трубами;
   - объём внутри = число труб × π/4 × внутренний диаметр² × длина трубы;
   - объём между трубами = объём габарита штабеля − наружный объём труб. Габарит — прямоугольник по следу штабеля на палубе, по высоте от верха клетки до верха штабеля. У пакета труб след — вся ширина между фальшбортами; у пирамиды габарит включает пустые углы над её склонами. И то и другое добавляет пустоты по краям — это в запас;
   - вес = чистый объём × доля × 1,025 т/м³;
   - доля: 30 % при надводном борте ≤ 0,015 L, 10 % при ≥ 0,03 L, между ними — линейно;
   - надводный борт = высота палубы над килем − средняя осадка;
   - вода увеличивает осадку и тем самым долю, поэтому расчёт повторяется, пока вес не перестанет меняться больше чем на 0,1 т (не больше 10 проходов);
   - вес воды кладётся в центр тяжести штабеля;
   - если у трубного груза нет внутреннего диаметра и нет поправки, его вода не считается, и проверка показывает ⚠.
3. **Лёд** — нормы 30 и 7,5 кг/м²:
   - 30 кг/м² на горизонтальную проекцию грузовой палубы. Над штабелем — на высоте верха груза, на свободной палубе — на высоте палубы;
   - 30 кг/м² на открытые палубы вне грузовой, на их высоте;
   - 7,5 кг/м² на боковую проекцию с каждого борта. Площадь — судна без груза плюс продольный профиль груза над палубой; профиль — наибольшая высота груза по длине палубы;
   - к боковой площади +5 %, к её моменту +10 % на леера и мелкие конструкции;
   - лёд симметричен и TCG не меняет;
   - если обледенение включено, а боковая площадь судна или площадь прочих открытых палуб не заданы, считается только то, что известно, и проверка показывает ⚠. Ноль — допустимое значение, а не «не задано».
4. **GM, крен, дифферент** — как сейчас: GM = KM − KG − ΣFSM/Δ.
5. **Осадки носом и кормой** (новое), если заданы LBP и LCF. Дифферент здесь — осадка носом минус осадка кормой, как в нынешнем расчёте («на нос» — больше нуля). Средняя — осадка по таблице гидростатики, она относится к LCF.
   - кормой = средняя − дифферент × LCF от кормового перпендикуляра / LBP;
   - носом = кормой + дифферент.
   - Положение LCF от кормового перпендикуляра зависит от точки отсчёта: при «от миделя» к нему прибавляется LBP/2. Так точка отсчёта впервые входит в расчёт.
   - С грузовой маркой сравнивается осадка на миделе, то есть среднее носом и кормой; без LCF — средняя по таблице.
6. **Справка по KN** — с пометкой «оценка», на вердикт не влияет:
   - GZ(θ) = KN(θ) − (KG + FSC)·sin θ − TCG·cos θ;
   - «GZ ≥ 0,2 м при угле ≥ 30°» — по наибольшему GZ на углах от 30° и выше;
   - угол максимума GZ — вершина параболы через узел с наибольшим GZ и два соседних;
   - угол заливания ограничивает только границу 40° (п. 2.2.1);
   - набор B 2.4.5: 0,070 м·рад до 15°, если максимум при 15°; 0,055 м·рад до 30°, если максимум при 30° и выше; между ними — 0,055 + 0,001·(30° − θmax); 0,03 м·рад от 30° до 40° или до угла заливания; GZ ≥ 0,2 м при угле ≥ 30°; максимум при угле не меньше 15°; GM ≥ 0,15 м.

## 5. Вердикт

Вердикт состояния, от худшего к лучшему:

| Итог | Когда |
|---|---|
| ✕ | GM < 0,15 м (IS Code A 2.2.4) — всегда, в том числе по оценке |
| ✕ | GM ниже предела по формуляру при осадке или водоизмещении, которые есть в таблице предела |
| ✕ | Осадка на миделе больше предельной |
| ⚠ | Предел по формуляру не задан |
| ⚠ | Осадка или водоизмещение вне таблицы предела |
| ⚠ | Водоизмещение вне таблицы гидростатики (оценка) |
| ⚠ | Танки не заданы ни в одном состоянии |
| ⚠ | Трубный груз на палубе без внутреннего диаметра и без поправки |
| ⚠ | Длина L не задана, а трубы на палубе есть |
| ⚠ | Обледенение включено, а боковая площадь судна или площадь прочих палуб не заданы |
| ✓ | Предел задан и выполнен, ни одного ✕ и ⚠ |

- Вердикт рейса — худшее из двух состояний. Вердикт плана — худший рейс, как и у остальных проверок (`checks.ts`).
- «Отход совпадает с приходом» — подсказка в панели, не ⚠.
- При пределе «макс. KG по водоизмещению» сравнивается KG с поправкой на свободную поверхность: KG + FSC ≤ KG предельный. Это то же, что GM ≥ KM − KG предельный.
- Строка статуса показывает худшее состояние текущего рейса: «GM 1.98 м (приход) ⚠». При равных итогах — состояние с меньшим запасом GM над пределом или, без предела, над 0,15 м.
- «Проверки» → «Остойчивость» перечисляет причины по рейсам и состояниям: «Рейс 2, приход: GM 1.12 м ниже предела 1.30 м при осадке 5.9 м».
- Справка по KN не меняет ни ✓, ни ⚠, ни ✕. Это меняет решение 3 группы B этапа 2, где невыполненный критерий давал ✕.

## 6. Интерфейс

### 6.1 Рабочая панель остойчивости

Это панель из спеки редизайна 8.5 с новыми группами. Открывается на месте палубы; назад — «← К палубе» или Esc.

Слева — данные по группам. У судна из библиотеки они заполнены и свёрнуты, сверху строка «Данные из: …».
- «Судно»: название, LBP, длина L, ширина, угол заливания, предельная осадка, набор критериев для справки.
- «Порожнее судно»: вес, KG, LCG, TCG, точка отсчёта.
- «Предел по формуляру» — новая: вид, таблица, источник.
- «Танки» с вкладками «Отход» и «Приход» и кнопкой «Скопировать из отхода».
- «Обледенение»: переключатель, площади, высоты.
- «Система координат палубы».
- «Гидростатика» и «KN-кривые» — таблицами с правкой ячеек и вставкой текстом.

Поля сохраняются по Enter или при уходе из поля.

Справа — результат с переключателем «Отход / Приход» и итогом ✓ / ⚠ / ✕ для обоих состояний:
- водоизмещение; осадки средняя, носом и кормой; крен; дифферент;
- GM с поправкой на свободную поверхность и запас до предела. Без предела — до 0,15 м с подписью «предел из формуляра не задан»;
- вода в трубах и лёд — отдельными строками с весом и высотой;
- причины ⚠ и ✕ списком;
- справка по KN: кривая GZ, критерии выбранного набора с пометкой «оценка»;
- блок «Не проверяется» (раздел 9);
- оговорка, всегда видна: «Оценка по введённым данным. Не заменяет одобренную Информацию об остойчивости и прибор загрузки судна».

Вне диапазона таблиц числа серые с пометкой «оценка», предупреждение стоит над ними крупнее значений (M5, как сейчас).

### 6.2 Входы

- «Судно» → «Остойчивость»: короткий итог (GM худшего состояния, ✓ / ⚠ / ✕ или «нет данных судна») и кнопка «Открыть остойчивость».
- Число GM в строке статуса.
- «Проверки» → «Остойчивость».

### 6.3 Что удаляется

- Раздел «Остойчивость судна» из сайдбара (`VesselStabilitySection`).
- `StabilityPanel`.

Спека редизайна удаляла их на этапе 4; теперь — на этапе 2а.

## 7. PDF

После таблицы грузов, перед креплением, стоит блок «Остойчивость» открытого рейса. При нескольких рейсах — «Остойчивость — рейс N из M».

- Таблица из двух строк, «Отход» и «Приход». Столбцы:
  - водоизмещение, т;
  - осадка средняя / носом / кормой, м;
  - крен, °;
  - дифферент, м;
  - GM, м;
  - предел GM, м — при пределе по KG пересчитанный в GM: KM − KG предельный;
  - вода в трубах, т;
  - лёд, т;
  - итог — словами: «выполнено», «нужна проверка», «не выполнено». Значков ✓ / ⚠ / ✕ в шрифте PDF может не быть.
- Под таблицей:
  - предел и его источник, или «Предел по формуляру не задан — проверено только по общему минимуму GM 0,15 м»;
  - причины ⚠ и ✕;
  - оговорка и строка «Не проверяется: …».
- Без данных судна — одна строка «Остойчивость: данные судна не заданы».
- Справка по KN в PDF не попадает.

## 8. Тесты

Unit (`stability.test.ts` и новые файлы рядом):
- Вода в трубах — арифметика на построенном примере с известным ответом: внутренний объём, габарит, доля на границах 0,015 L и 0,03 L и между ними, сходимость проходов.
- Вода в трубах на данных «Кузнецова» — проверка правдоподобия, а не совпадения. Труба известна по пресету (Ø813×30,2, покрытие 72 мм), но длины L и границы штабеля в документе нет. При L = LBP метод даёт около 80 т, при L около 86 м — около 86 т; в документе 87 т. Тест проверяет диапазон 75–103 т и записывает допущения в комментарий.
- Лёд: горизонтальная и боковая части, +5 % и +10 %, верх груза против свободной палубы.
- Предел обоих видов: интерполяция, границы таблицы, «вне таблицы».
- Каждая строка таблицы вердикта из раздела 5, худшее из двух состояний.
- Справка по KN: поправка TCG·cos θ, правило «≥ 30°», вершина параболы, угол заливания только на 40°, набор B 2.4.5.
- Осадки носом и кормой при обеих точках отсчёта.
- Перенос `minGM` и `variableWeights`.

`page.test.tsx` и e2e:
- открыть панель из «Судно» и из строки статуса, вернуться по Esc;
- вставить таблицу предела и получить ✓, затем ✕ после добавления груза;
- включить обледенение и увидеть рост KG и падение GM;

## 9. Не проверяется

Написано в панели и в PDF:
- критерий погоды и, для судов снабжения, альтернативные критерии, которые устанавливает администрация. Они учтены, только если учтены в введённом пределе;
- аварийная остойчивость;
- общая прочность корпуса;
- плотность забортной воды, отличная от 1,025 т/м³;
- таблицы предела по нескольким дифферентам: вводится один столбец;
- угол заливания как функция осадки: вводится одно число.

## 12. Открытые вопросы

- **7,5 кг/м² «с каждого борта».** Считаются оба борта, это в запас. Если правила флага или РС считают иначе, коэффициент меняется в одном месте.
- **Граница штабеля для объёма между трубами.** Берётся след штабеля на палубе (4, п. 2). Если в формуляре или проекте перевозки граница другая, ответ отличается на 5–10 %. Для точной цифры есть поправка «Вода в трубах, т».
- **Боковая площадь «Кузнецова».** 854,4 м² взяты из проекта перевозки труб и, вероятно, уже включают груз. Тогда профиль груза учитывается дважды — в запас; в пометке «Откуда данные» это сказано.
