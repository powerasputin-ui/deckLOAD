# Этап 0: логические исправления в текущем интерфейсе

План реализации этапа 0 из спецификации `docs/superpowers/specs/2026-10-21-deckload-redesign-design.md` (разделы 8.6 и 13).

## Как работаем

- Интерфейс не перестраивается: исправления делаются в нынешних компонентах.
- На каждое исправление сначала пишется тест, который падает до правки, потом правка. Пункты «из кода» исправляются, только если тест их воспроизвёл. Не воспроизвёлся — пункт закрывается с пометкой в описании коммита.
- Группа — отдельный коммит. После каждой группы зелёные `bun run test:ci`, `bun run lint`, `npx tsc --noEmit` и e2e-тесты затронутых сценариев. Полный e2e — в конце этапа.
- Тексты меняются вместе с тестами, которые ищут элементы по этим подписям.

## Новые данные

- `deck.vesselTemplateId?: string` — какое судно из библиотеки применено (группа E).
- `deck.deckStrengthChoiceTPerM2?: number` — выбранный лимит прочности палубы (группа E).

Оба поля необязательные. Старые расчёты открываются без миграции.
